MongoDB Basics: Core Concepts

Understanding How MongoDB Stores and Organizes Data

Before working with MongoDB queries and commands, it is important to understand how MongoDB stores, organizes, and relates data. These concepts form the foundation of CRUD operations, indexing, aggregation, and schema design.

1. Data Hierarchy in MongoDB

Database → Collection → Document

MongoDB stores documents inside collections, and collections inside databases. This structure replaces the table-based model used in relational databases.

Database

A database is the top-level container in MongoDB. One MongoDB server can host multiple databases, usually one per application.

  • Contains multiple collections
  • No fixed limit on collections
Example: CodingGitaBTechDB

Collection

A collection is a group of related documents. It is similar to a table in SQL, but without a fixed schema.

  • Documents can have different fields
  • No column enforcement
Example: students

Document

A document is a single record stored in BSON format as key–value pairs. 

{
  "name": "Arjun",
  "rollNumber": "12345",
  "department": "CSE",
  "year": 3,
  "coursesEnrolled": ["Data Structures", "DBMS", "AI"],
  "age": 21
}
Each student is stored as one complete document, reducing the need for joins.

2. BSON (Binary JSON)

MongoDB stores data internally using BSON, a binary representation of JSON.

  • Faster read and write performance
  • Supports advanced data types
  • Optimized for indexing

BSON Date Example

{
  "name": "Krishna",
  "enrollmentDate": { "$date": "2021-08-15T00:00:00Z" }
}

3. Schema-less Nature of MongoDB

MongoDB does not enforce a fixed schema. Each document can evolve independently.

Initial Document

{
  "name": "Priyasha",
  "rollNumber": "67890",
  "department": "CSE",
  "year": 2
}

Updated Document

{
  "name": "Priyasha",
  "rollNumber": "67890",
  "department": "CSE",
  "year": 2,
  "skills": ["Java", "MongoDB", "React"]
}
Older documents remain valid even when new fields are added.

4. Embedded Documents vs Referencing

Embedding

{
  "name": "Yashvi",
  "rollNumber": "112233",
  "department": "CSE",
  "year": 1,
  "courses": [
    {
      "courseCode": "CS101",
      "courseName": "Data Structures",
      "credits": 4
    }
  ]
}
  • Faster reads
  • One-to-few relationships
  • Data accessed together

Referencing

{
  "name": "Yashvi",
  "courses": [
    { "$ref": "courses", "$id": "CS101" },
    { "$ref": "courses", "$id": "CS102" }
  ]
}
  • Data shared across documents
  • Large or frequently changing data

Embedding vs Referencing

Aspect Embedding Referencing
Read Performance Fast Slower
Data Duplication Possible Minimal
Best For One-to-few One-to-many
Rule of Thumb: If data belongs to one document → Embed If data is shared → Reference
