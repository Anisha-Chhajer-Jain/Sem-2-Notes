1. Negation Operators

Operator Meaning Logic
$not Negates a condition NOT
$nor No condition matches NOT (A OR B)

$not Example

db.jobs.find({
  experience: { $not: { $gt: 2 } }
})
$not must be applied at the field level, not at the query root.

2. $nor – Multiple Condition Negation

db.jobs.find({
  $nor: [
    { company: "Amazon" },
    { location: "Bangalore" }
  ]
})
This means: NOT (company = Amazon OR location = Bangalore)

3. $regex – Pattern Matching

Pattern Meaning
^ Starts with
$ Ends with
.* Any characters

Starts With “Senior”

db.jobs.find({
  role: { $regex: "^Senior" }
})

Ends With “Developer”

db.jobs.find({
  role: { $regex: "Developer$" }
})

Case-Insensitive Match

db.jobs.find({
  role: { $regex: "backend", $options: "i" }
})
Regex can cause full collection scans. Avoid it in high-traffic APIs.

4. $expr – Field-to-Field Comparison

Use $expr when comparing one field with another field or expression.

Salary > Experience × 5 Lakh

db.jobs.find({
  $expr: {
    $gt: ["$salary", { $multiply: ["$experience", 500000] }]
  }
})

Experience < Salary / 10 Lakh

db.jobs.find({
  $expr: {
    $lt: ["$experience", { $divide: ["$salary", 1000000] }]
  }
})
Operator Purpose
$gt Greater than
$lt Less than
$add Addition
$multiply Multiplication
$divide Division

5. Operator Composition

db.jobs.find({
  role: { $regex: "Backend", $options: "i" },
  experience: { $gte: 3, $lte: 5 },
  location: "Bangalore",
  salary: { $gt: 1000000 }
})
This is how real backend filtering looks in production systems.

6. Performance Awareness

Mistake Impact
Regex without ^ Full collection scan
Overusing $expr Slower queries
Inconsistent schema Wrong results
Too many conditions Index misuse
Design schema for queries — not queries for schema.

Key Takeaways

  • Use $not and $nor for exclusion logic
  • Apply regex carefully and sparingly
  • Use $expr only when fixed values are insufficient
  • Compose multiple operators for real queries
  • Always think about performance
